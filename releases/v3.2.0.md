# WP Manager Pro v3.2.0 — Syntax-highlighted code editor (CodeMirror 6)

**Released:** 2026-05-13

## Summary

Replaces the bundled code editor across **File Manager** and **Snippets** with CodeMirror 6, fixing the long-standing issue where the editor rendered without syntax colours on sites with strict CSP, firewalls, or offline networks.

Closes [#2](https://github.com/nurkamol/wp-manager-pro/issues/2) — *[Feature]: Syntax highlighting for PHP editor in File Manager*.

---

## Why

The previous editor was Monaco via `@monaco-editor/react`, which by default loads its language workers from a public CDN (jsdelivr). On many production WordPress installs that load is blocked — Monaco itself initialised, but tokens were never coloured, so users saw plain monochrome text. This was the exact symptom reported in issue #2.

CodeMirror 6 is bundled directly into the plugin. No external requests, no workers, no CDN dependency — syntax highlighting works everywhere, including air-gapped environments.

---

## What changed

### Editor swap
- **File Manager** — code editor for any `.php`, `.js`, `.ts`, `.css`, `.html`, `.json`, `.xml`, `.svg`, `.md`, `.yml`, etc.
- **Snippets** — both the inline editor inside the create/edit dialog and the fullscreen overlay.
- New shared `src/components/CodeEditor.tsx` component — single source of truth for theme, basic setup, and language mapping. Used by both pages.

### Language support
PHP · JavaScript · TypeScript · CSS · HTML · JSON · XML · SVG · Markdown · YAML — all with the **One-Dark** theme.

### CSS specificity fix
The `.wmp-app span { color: inherit }` rule in `src/index.css` (specificity 0-1-1) was overriding CodeMirror's per-token highlight classes (specificity 0-1-0). Added `:not(.cm-editor *)` to the selector so CodeMirror's token colours render correctly without losing the WP-admin colour bleed protection elsewhere.

### Plain-PHP parsing
Pass `{ plain: true }` to `@codemirror/lang-php`. Many WordPress files (e.g. `wp-config.php`) have no closing `?>` tag; without `plain: true`, the parser would start in HTML mode and partially tokenise the file. Mixed HTML/PHP files like `wp-trackback.php` still highlight correctly.

## Bundle / dependency changes

| Change | Detail |
|--------|--------|
| Removed | `@monaco-editor/react` |
| Added | `@uiw/react-codemirror`, `@codemirror/theme-one-dark`, `@codemirror/lang-php` (with `plain` mode), `@codemirror/lang-javascript`, `@codemirror/lang-css`, `@codemirror/lang-html`, `@codemirror/lang-json`, `@codemirror/lang-xml`, `@codemirror/lang-markdown`, `@codemirror/lang-yaml` |
| External requests on load | **Zero** (was: ~5 MB worker payload from jsdelivr) |
